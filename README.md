# ДЗ №1 «Зоопарк» — шаблон проекта

Консольное приложение для управления зоопарком на Go. Репозиторий — стартовый
шаблон: структура, проверки и правила уже настроены, логику дописываете вы.

## Требования

- Go 1.26+ (`go version`)
- golangci-lint v2 — [установка](https://golangci-lint.run/docs/welcome/install/) (проще всего: `go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@latest`)
- mockery v3 — генерация моков (`go install github.com/vektra/mockery/v3@latest`), нужен только для `make mocks`

## Быстрый старт

```bash
make help    # все команды
make run     # запустить зоопарк
make test    # тесты
make check   # форматирование + vet + линтеры + тесты — прогонять перед сдачей
```

## Порядок работы

1. **Спецификация.** Сначала заполните `docs/spec.md`: цель, команды, сценарии
   с примерами ввода-вывода, ограничения, критерии приёмки. Код, написанный
   до спецификации, на ревью не принимается.
2. **ADR.** Основные решения — структура пакетов, формат команд, хранение
   состояния, обработка ошибок — оформите в `docs/adr/` по шаблону
   `0000-template.md` **до** начала кодирования. Заполненный пример —
   `0001-console-repl-no-tui.md`.
3. **Реализация.** Только после спецификации и ADR пишите код. Перед каждым
   коммитом прогоняйте `make check`.

Порядок проверяется историей коммитов: спецификация и ADR должны появиться
в репозитории раньше кода.

## Структура

```
cmd/zoo/            точка входа (тонкий main)
internal/zoo/       предметная область: животные, вольеры, зоопарк (+ тесты-образцы)
internal/cli/       текстовое меню (REPL), работает только через internal/zoo
docs/spec.md          спецификация — заполняется ДО кода (см. «Порядок работы»)
docs/adr/             архитектурные решения: шаблон 0000 + примеры 0001, 0002
docs/prompting.md     инструкция по промптингу: фреймворки, техники, чек-лист
AGENTS.md           инструкция для AI-агента (читайте сами — это правила проекта)
AI_USAGE.md         журнал использования ИИ — обязателен к сдаче
.golangci.yml       единый набор линтеров проекта (включая gosec и gocyclo)
.mockery.yml        генерация моков (make mocks) — пример в internal/zoo/zoo_test.go
Makefile            все команды проекта
.github/workflows/  CI: build + test + lint на каждый push
skills/             навыки для AI-агентов (.skill — устанавливаются в агента)
```

## Навыки для AI-агентов

В `skills/` лежат устанавливаемые навыки (`.skill` — это zip-пакет с SKILL.md):

- `go-modern` — современный идиоматичный Go по гайдлайнам JetBrains (версия берётся из go.mod).
- `asd-ste100` — переписывание английского техтекста по ASD-STE100 + линтер.
- `asd-ste100-ru` — то же для русского: контролируемый упрощённый технический русский.
- `c4-diagrams` — построение C4-диаграмм (методология + Mermaid/PlantUML/Structurizr).

Установите навыки в свой агент (Kimi/Claude Code/Junie) до начала работы —
`AGENTS.md` ссылается на `go-modern` как на источник идиом.

Как формулировать запросы к агенту — см. `docs/prompting.md`.

## Как сдавать

Сдача — merge request (в GitHub он же pull request) из ветки `dev` в **пустой**
`master`. Diff такого MR содержит весь проект целиком, поэтому проверяющий
может комментировать любую строку и задавать вопросы прямо по коду.

Настройка репозитория (один раз, до начала работы):

```bash
git init
git checkout -b master
git commit --allow-empty -m "chore: пустой master"
git push -u origin master
git checkout -b dev
git push -u origin dev
```

Дальше вся работа — только в `dev`: спецификация → ADR → код
(см. «Порядок работы»).

Сдача:

1. Убедитесь, что `make check` зелёный.
2. Откройте MR из `dev` в `master`. В описании — ссылка на `docs/spec.md`
   и список ADR.
3. В `master` ничего не коммитьте и не мержите до аппрува проверяющего.
4. Замечания исправляйте новыми коммитами в `dev` — они автоматически
   попадают в тот же MR. На комментарии отвечайте в обсуждении, не удаляйте их.
5. После аппрува MR мержит проверяющий.

## Правила сдачи

1. MR `dev → master` открыт по инструкции выше; спецификация и ADR
   закоммичены раньше кода (см. «Порядок работы»).
2. `make check` зелёный, CI в MR зелёный.
3. `AI_USAGE.md` заполнен честно и по ходу работы.
4. Внешние зависимости — только по согласованию с преподавателем.

## Если модуль нужно переименовать

Плейсхолдер `example.com/zoo` замените на путь своего репозитория:

```bash
go mod edit -module github.com/<you>/zoo
# и обновите импорты + local-prefixes в .golangci.yml
```
