# C4 Diagrams

C4 — методология Саймона Брауна: четыре уровня абстракции для описания архитектуры ПО. Сама по себе C4 не нотация рисования — диаграмму пишут в Mermaid, PlantUML (макросы C4-PlantUML), Structurizr DSL или LikeC4.

## Уровни C4

| Уровень | Аудитория | Что показывать | Типичные ошибки |
|---|---|---|---|
| L1 System Context | Все, включая не-инженеров | Система целиком, пользователи, внешние системы | Внутренние контейнеры на контекстной диаграмме |
| L2 Container | Инженеры и техлиды | Приложения и хранилища (web, API, DB, очередь) + технологии | Классы и функции; более ~20 блоков |
| L3 Component | Инженеры команды | Компоненты внутри одного контейнера | Показывать сторонникам; рисовать для всех контейнеров сразу |
| L4 Code | Почти никогда | Классы/интерфейсы | Рисовать вручную — генерировать из кода или пропустить |

Дополнительно: Deployment (инфраструктура и размещение контейнеров) и Dynamic (сценарий взаимодействия, замена sequence-диаграммы).

## Правила методологии

1. Одна диаграмма = один уровень абстракции. Не смешивай контейнеры и компоненты.
2. Каждый элемент: имя + технология (для L2/L3) + одно предложение описания.
3. Каждая связь подписана действием и протоколом: «Читает и пишет», «JDBC».
4. До ~15–20 блоков на диаграмму; больше — раздели по уровням или по сценариям.
5. Описывай систему как она есть (или как запрошено), а не «идеальную».
6. Уровень L4 вручную не поддерживают — генерируй или пропускай.

## Выбор нотации

```text
Куда попадёт диаграмма?
├─ README / GitHub / GitLab / wiki (рендер в браузере, без установки)
│   → Mermaid (C4Context/C4Container; на L3 при глюках — flowchart + subgraph)
│   → references/mermaid-c4.md
├─ Файлы .c4/.likec4, LikeC4 CLI, интерактивные диаграммы
│   → СТОП: используй навык likec4-dsl, он покрывает DSL полностью
├─ Долгоживущая модель: одна модель → несколько видов, валидация ссылок
│   → Structurizr DSL (экспорт в PlantUML/Mermaid)
│   → references/structurizr-dsl.md
└─ Качественная раскладка (Graphviz), рендер в CI, PNG/SVG для документов
    → C4-PlantUML
    → references/plantuml-c4.md
```

Если нотация не задана — предложи Mermaid для разовой диаграммы и Structurizr DSL/LikeC4 для модели, которую будут поддерживать.

## Процесс

1. Уточни (или реши сам и скажи): уровень C4, аудитория, нотация.
2. Собери элементы и связи из описания/кода; подпиши технологии и протоколы.
3. Напиши источник в выбранной нотации.
4. Проверь: `mmdc` для Mermaid, `structurizr validate` для DSL, `plantuml -checkonly` для PlantUML (плюс зрительная проверка: PlantUML молча рисует «выдуманные» элементы при опечатке в имени).
5. Отдай источник; рендер приложи, если есть тулчейн.

## Антипаттерны

| Антипаттерн | Почему плохо | Что делать |
|---|---|---|
| Все 4 уровня в одной диаграмме | Теряется абстракция | Одна диаграмма — один уровень |
| Огромная диаграмма «всё системы» | 20+ блоков не читаются | L1 + отдельные L2 по подсистемам |
| Связи без подписей | Непонятно, что за взаимодействие | Действие + протокол на каждой стрелке |
| include C4-PlantUML с ветки master | Макросы переименуют — диаграмма сломается | Пиновать версию: `.../v2.12.0/C4_Container.puml` |
