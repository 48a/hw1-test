# Упрощённый технический русский (адаптация ASD-STE100)

ASD-STE100 — стандарт контролируемого английского для авиационной документации. Официального русского стандарта нет (есть отраслевая практика Simplified Technical Russian компании АВИАОК). Этот навык — адаптация принципов STE к русской грамматике для текстов, которые читает человек-непрофессионал или AI-агент без права переспросить.

Полный каталог правил с примерами «до/после»: `references/pravila.md`. Готовые разборы: `examples/primery.md`.

## Два режима

Выбери режим до переписывания; если пользователь не указал — выведи из типа текста.

- **Строгий** — процедуры, инструкции, сообщения об ошибках, описания инструментов, тексты для агентов. Применяй все правила, включая жёсткие ограничения длины и дисциплину «один термин — одно значение».
- **Свободный (в духе STE)** — README, описания PR, пояснительная проза. Структурные правила применяй полностью, лексические — как рекомендацию.

## Структурные правила (применять уверенно)

1. Одно предложение — одна инструкция или одна мысль. Максимум ~20 слов в инструкции, ~25 в описании.
2. Условие — перед командой: «Если флаг включён, перезапустите службу», а не «Перезапустите службу, если флаг включён».
3. Сообщение об ошибке строится по схеме: что произошло → причина → что делать.
4. Действующее лицо явно, залог активный: «Сервер отклоняет запрос», а не «производится отклонение запроса».
5. Инструкции — в повелительном наклонении: «Установите», «Проверьте». Не «вам следует установить».
6. Простые времена. Настоящее — для фактов, прошедшее — для отчётов. Никаких «была произведена обработка».
7. Точка с запятой запрещена — раздели на предложения.
8. Не телеграфный стиль: предлоги и союз «что» сохраняются. STE — коротко, но грамматически полно.
9. Процедура — нумерованные шаги, один шаг = одна строка = одно действие.
10. Цепочки существительных в родительном падеже — не более двух: «настройки модуля» нормально, «кнопка панели управления модулем системы» — нет.

## Лексические правила (направление, не сертификация)

- Один термин — одно значение во всём документе: не чередуй «проверьте/убедитесь/верифицируйте».
- Глагол вместо отглагольного существительного: «проанализируйте лог», а не «выполните анализ лога».
- Без оценочных и маркетинговых слов: «важно отметить», «критически необходимо», «надёжный», «бесшовный».
- Без хеджирования: «возможно», «скорее всего», «как правило» — или факт, или явное условие.
- Термин определяется при первом использовании; проектный глоссарий разрешён и приветствуется.

## Процесс

1. Прочитай исходный текст один раз на смысл — не переписывай, пока не понял, что текст обязан сохранить.
2. Иди по предложениям. Отмечай нарушения правил из списков выше и каталога `references/pravila.md`.
3. Перепиши каждое нарушение. Не теряй ни факт, ни условие, ни квалификатор области действия. Если короткая формулировка теряет точность — оставь длинную и пометь `Оставлено как есть:` с причиной.
4. По умолчанию выдай только переписанный текст — без преамбулы и сводки. Если просят обоснование («покажи diff», «какие правила нарушены») — выдай таблицу «до/после/правило».

## Границы

- Не для художественных текстов, маркетинга и любого текста, где голос и нюанс — суть.
- Навык правит форму, не содержание: пустой абзац станет коротким и чистым, но останется пустым.
- Это адаптация принципов, а не официальный стандарт; для сертифицируемой документации используйте ASD-STE100 (англ.) или отраслевой стандарт организации.
