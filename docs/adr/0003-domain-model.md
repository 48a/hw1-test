# 0003. Модель транспорта и вещей через композицию

Дата: 2026-10-26

## Статус

Принято

## Контекст

Вместо зоопарка нужен учёт прокатной техники и вещей. Не все объекты
потребляют энергию. Новый вид транспорта не должен менять расчёт отчёта.

## Решение

Заменить `internal/zoo` на `internal/domain`, `cmd/zoo` на `cmd/rental`.
Оставить `internal/cli` для консоли. Модуль в `go.mod` не переименовывать.

В домене использовать три интерфейса: `Inventory` — название и номер,
`EnergyConsumer` — суточная энергия, `Transport` — инвентарь, простота
и исправность. Общие поля собрать в неэкспортируемых структурах и встраивать
их в конкретные типы. Отдельный интерфейс для вещей не нужен.

Энергию хранят электросамокат, электровелосипед и зарядный шкаф.
Шлем, велосипед и док-станция без зарядки её не потребляют.
Новичкам подходит только принятый транспорт с простотой от 6 включительно.

## Альтернативы

- Одна структура с полем «вид» — отчёт пришлось бы менять для новых видов.
- Большая иерархия интерфейсов — добавляет типы без пользы для задания.

## Последствия

- Плюсы: короткие интерфейсы, общие поля без копирования, домен без ввода-вывода.
- Минусы/риски: конструкторы похожи; нулевые значения требуют проверки при приёмке.
