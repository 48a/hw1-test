# 0005. Техосмотр через зависимость конструктора

Дата: 2026-10-26

## Статус

Принято

## Контекст

Транспорт можно принять только после техосмотра. Тест должен уметь
изменить решение сервиса независимо от технического состояния транспорта.

## Решение

Передавать `ServiceCenter` с методом `Inspect(Transport) bool`
в конструктор `Park`. Обычная реализация `BasicServiceCenter` принимает
исправный транспорт. Парк сначала проверяет данные и уникальность номера,
затем вызывает сервис. Отказ не меняет баланс и не занимает номер.
Вещи добавляются без техосмотра. Через добавление вещей нельзя обойти
техосмотр транспорта.

В тестах использовать мок, сгенерированный `make mocks` через mockery.
Использовать уже разрешённый в шаблоне testify, новых зависимостей не добавлять.

## Альтернативы

- Проверять исправность внутри парка - нельзя независимо подменить решение техосмотра.
- Контейнер зависимостей - для одной зависимости достаточно конструктора.

## Последствия

- Плюсы: правило техосмотра отделено от учёта; тест проверяет решение и число вызовов.
- Минусы/риски: ещё один интерфейс, оправданный подменой в тестах.
