# 0004. Курс и взвешенный итог

Дата: 2026-11-23

## Статус

Принято.

## Контекст

Оценки должны соответствовать рубрикатору, а пропуски не должны завышать итог.

## Решение

`Course` - корень агрегата: студенты, критерии и оценки меняются через его методы.
`Student` и `Criterion` - сущности с ID; `Evaluation` - неизменяемое значение.
Фабрика `Course.Evaluate` проверяет студента, критерий и диапазон перед созданием оценки.
Доменный сервис `Calculator` считает взвешенный процент из текущего состояния.
Стратегии `MissingAsZero` и `RequireAll` задают учёт пропусков: текущий или окончательный итог.
Итог не сохраняется. Числа должны быть конечными; максимум и вес положительны.

## Альтернативы

- Раздельные агрегаты для каждого списка - усложняют проверку связей.
- Среднее сырых баллов - не учитывает разные максимумы и веса.

## Последствия

- Плюсы: все инварианты в модели; исправление сразу меняет итог.
- Минусы: агрегат хранит весь небольшой учебный курс.
